## Description

A Glitch idea tab in Orca no longer drops back to "Connect this browser" mid-session and asks for a typed code.

**Why it happened.** Orca destroys and rebuilds a browser page's webview when its worktree falls out of the four most recent hidden ones, or when the SSH route to the host is re-prepared, and reloads the saved address. The cookie survives; sessionStorage, and the tab secret in it, does not. Measured on Orca: a plain reload and ten tab switches keep the pairing; a page with its sessionStorage gone and the saved address reloaded shows the connect panel.

**What changes.**
- `browser-open --browser orca --reconnect <binding>` re-pairs the recorded Orca tab in place: it reads the page's pairing mark (`orca eval`) and only when the page says "unpaired" the service issues a fresh one-time code for the same agent generation, which `orca goto --page` loads into that same page as `#pair=<code>`. No tab is created or closed, the agent keeps its credential and lease, and the code is never printed. A paired tab is never rotated (`tab_still_paired`); an unrecorded or unreadable page changes nothing.
- The page marks its state on `<html data-idea-pairing>` (paired / unpaired / replaced, no secret), and a tab that was paired before says the terminal reconnects it instead of asking for a code first.
- SKILL.md and the command reference: the background events loop runs `--reconnect` after every wait; "reconnect" from the operator runs it once. A new tab still asks for a code.

**Verification.** 11 new tests (tests/test_rebuilt_tab_repair.py, 10 red before the change); web tests 608/608; touched Python suites green, full suite with only the two environment-dependent reds that main shows on this host. On Orca: paired tab left alone; simulated rebuild then `--reconnect` re-paired the same page with the agent connected; ten tab switches, no connect panel; the live tab secret found nowhere in the runtime folder, store, page record, results or Orca logs. A real hidden-worktree eviction was not driven.
