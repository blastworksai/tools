# report-files-v1 wire contract

`codec.luau` is the maintained strict byte contract shared by ORCH+ and SPAWN. `sync.py` vendors it into those packages as `wire/codec.luau`, and vendors the canonical `mailbox_reply.jq` and `mailbox_worker.ps1` validators into SPAWN. Edit the shared sources, not their generated copies. ORCH-only checkpoint, landing-proof, signer and scope policy lives in `plugins/tern/ORCH+/workflow_rules.luau`.

```sh
python3 shared/report-files-v1/sync.py
python3 shared/report-files-v1/sync.py --check
```

The codec owns strict JSON/UTF-8, closed schemas, hashes, canonical Base64, framing and capability validation. Native JSON parsing alone is not a substitute. Runtime origin, current authority and workflow authorization remain in their existing owners.

Managed dispatch requests and ordinary response frames remain limited to 8,192 UTF-8 bytes, including prefix and escaped outer JSON. Only a `status` response may use the separate 16,384-byte inspection envelope, so a valid maximum-sized original still fits with its status metadata. A `found` outcome must independently encode under its original operation's ordinary limit; invalid, oversized and nested-status originals are rejected. The larger inspection envelope grants no execution or replay permission and changes no report, mailbox or launch bound.

Managed project START uses the negotiated `project-start-v1` capability in addition to `coordinator-control-v1`. The closed `project_start` reply and `PROJECT_START_CLAIM` report share the exact payload `{owner_id, owner_generation, activation_token, orch_project_id, project_revision, decision_context}`. Owner/project identifiers are issued identities, generations/revisions are positive integers, and activation/context values are 64 lowercase hexadecimal characters. The claim report also requires the reply's exact `action_id` and `action_revision`. Extra fields, missing capabilities and missing action correlation are refused.

The coordinator consumes the complete immutable reply, records its local helper claim, publishes that correlated claim report once, waits for its real accepted receipt, then resolves the local claim. Receipt or a conversation message is not a project START. Existing reply outboxes, manifest-last publication, receipt chains and retained execution journals remain the only transport; replay never creates a second grant. Old saved helper bundles are not silently advertised as supporting the new capability.

An accepted receipt acknowledges a consumed report fact; it does not independently authorize implementation. A correctly authenticated claim for an exact issued START whose owner or subject was definitively revoked may receive that receipt as a refused fact: resolve its local journal entry, but release no work. Malformed, foreign and not-yet-proven claims do not gain acceptance from this exception. Only the host's validated current claim transition releases the captured work.

For explicit retirement of a positively stopped coordinator, `mailbox_retire` in `mode="retire"` may carry a sorted, bounded `withdrawn_starts` array of `{reply_seq,message_id,message_sha256}`. Both START capabilities are required. It names only the exact complete unread tail of irrevocably closed, unclaimed project START replies; all other obligations and the original publication/wake must be settled. Physical retirement verifies the actual journal, consumed floors, receipt chain and complete message bytes/bindings. Withdrawal never fabricates a consumer ACK, advances its cursor or retires an uncertain effect. Ordinary compaction is unchanged.

Catalog records optionally declare `provider_family`: a lowercase, nonblank, control-free string of at most 96 UTF-8 bytes. SPAWN owns these declarations; consumers do not infer a second family map. `declare_provider_families` uses the admitted action envelope, current `record_revision` and 1–32 unique `{record_id, provider_family}` declarations. SPAWN atomically fills absent declarations, accepts identical ones and refuses conflicts; a resolved response carries `{config_revision, applied, families}`. The required `families` array returns the canonical saved value for every requested record exactly once; consumers match the exact request ID set and verify a fresh catalog before clearing migration obligations. This metadata does not change USAGE account-definition fingerprints, confirmed profile bindings or OMP associations. Executable/account/profile edits retain their existing identity semantics.

`mailbox_inventory` is a read-only admitted observer, not an effect grant. Its `stale_ms` threshold is 1–315360000000; SPAWN observes only retained targets belonging to the current logical session. Pending observations carry no result; completed `inventory` results contain `observed_at_ms`, actual regular `open_files`, `stale_files` and `mailboxes` (maximum 32, covering the complete retained-worker bound including reviewers and rollover generations). File counts are bounded at one million and stale files cannot exceed open files. The installed target helper's `inventory` mode accepts the existing root/handle/identity arguments and threshold in `selected`, refuses links/reparse points and reports file modification ages without writing or acquiring admission. POSIX timestamps have one-second resolution. These are observed stored files, not operating-system file-descriptor counts; inventory never deletes files.

Coordinator `add_source` template proposals may include `source.custom_fields`, an object with at most 16 field values. Names use lowercase slugs of at most 32 bytes and cannot be `input`; values are NUL-free UTF-8 strings of at most 2048 bytes, including empty strings. Template configuration remains authoritative for declared/required fields.

READY, HEARTBEAT and CHECKPOINT optionally carry **one** context representation: `context_used_pct` (integer 0–100), or the closed object `context_snapshot={current_tokens,window_tokens,observed_at_ms,first_turn_tokens?}`. Counts/timestamps are safe nonnegative integers; the window is positive and neither count exceeds it. `first_turn_tokens` is optional for percentage mode but required for calculated headroom. Unknown keys, unsafe/fractional counts and both representations together reject the report. Counts describe actual runtime context occupancy, not billing/output totals. The owning reducer binds freshness, stable baseline/window and worker generation; a valid wire object alone does not authorize rollover.

`mailbox_allocation` is an admitted read-only observer for current and legacy journal allocations, independent of consumed outcomes. Its required closed `target` is `{logical_session_id, worker_id, worker_generation, launch_request_id, work_id, enrolment_sha256}` and must belong to the outer session. A positive `allocation` result echoes that exact target and carries exactly `{state="none"}` or `{state="retained", provision=<full provisioned payload>}`. Retained evidence reuses the ordinary provisioned schema. Unknown or incomplete evidence remains uncertain, never absence. Existing request/controller/admission fences apply; `status` found outcomes remain unchanged and do not carry allocation metadata.

Both mailbox observers use only the admitted OBSERVE envelope and their operation-specific fields. The mailbox ACTION binding, enrolment token, handle, expected generation and serial ledger are not observer request fields.

A `launch` request may carry optional `model` (nonblank, at most 200 bytes, no control characters, no leading `-`) and `effort` (lowercase letters, at most 32 bytes): the owner's choice for that one launch. No other operation accepts them, so an older peer refuses such a request as an invalid closed schema instead of ignoring the fields, and a request without them is byte for byte what it was. SPAWN applies its capability table (`plugins/tern/SPAWN/selectors.luau`, vendored read-only into ORCH+ by `sync.py`) and never edits the saved record.

## Report assembly

ORCH+ owns persisted report assembly. `assembly_start(manifest_bytes, manifest_sha256, binding)` creates a bounded JSON-serializable prefix. `assembly_push(state, chunk_bytes, chunk_sha256, binding)` validates the arriving object and appends its Base64 slice without replaying prior chunks. Slices may split a UTF-8 character; only complete logical bytes are decoded as the report.

Final digest, schema and binding validation precede intake. ORCH+ commits its receipt cursor before publishing an ACK. A rejected complete message preserves its bytes for the rejection path. Restoring an assembly validates its prefix, hashes and size; the authority enforces four assemblies and the existing 64-KiB logical-message limit.

SPAWN reads only the requested validated mailbox object. It still assembles and validates an entire reply before publishing that reply's manifest. Staged authorization and durable active reads are unchanged.

For actual report-path qualification, use `--scenarios reports` instead of `--suites all` and supply `--baseline-archive` with a verified archive of the pinned comparison source. It opens an ordinary isolated GUI, initializes actual authorities, launches a real managed deterministic report producer in a disposable repository, exercises staged authorization, rejects forged-origin/replayed authorization, checks cursor-before-ACK ordering and reloads with an outstanding immutable ACK. This is not provider-backed agent-workflow or final showcase proof.

`--scenarios project-start-fixture` exercises exact, uninstrumented SPAWN/ORCH packages with a deterministic local-terminal coordinator and physical shipped helpers. It covers owner-approved held-plan import, immutable typed START publication, native reload before claim, real consume/claim/report/accepted receipt, background settlement without focus/session changes, a single foreground child launch, and a second reload continuing both accepted workers without duplicating the grant or child. Each asynchronous observation phase has its own bounded scenario wait; native callback and production effect deadlines are unchanged. This is offline terminal-transport qualification, not real-provider, native-OMP or remote-device qualification. Failed publication remains covered separately by `orch:workflow/project_start_failures`; the owner journey does not fault-inject publication.

Receipts retain the complete required, selected and unrun inventories for each requested scenario; a selected-cell pass is not full C3 qualification. Omit `--runtime-cases` to run every cell in the selected scenarios. Selection never grants provider consent. Full qualification requires the complete required-cell union as well as the native owner suites, not merely a passing partial receipt.

The current C6 policy (except readiness), lifecycle, recovery, rulings and repository scenarios select a real Native OMP coordinator. They therefore require explicit `--provider-coordinator` and `--provider-agent-dir` pointing at an already approved existing profile; credentials must not be copied. Missing consent is reported before native effects. This harness choice is not a product restriction: normal verified SPAWN preparation can provide coordinator capability to supported local-terminal agents too. Fixture imports must not fabricate it. Hybrid consent does not change `--provider-readiness` or `conversation-provider`, and offline `conversation-fixture` remains offline.

Hybrid evidence is genuine coordinator startup/model/binding, activation and exact helper-produced proposals, with deterministic terminal workers retained for controlled task/check/negative scenarios. It is not genuine-provider-worker qualification. Rollback faults arm only after coordinator activation and select the target launch, not setup diagnostics. Handover uses actual Native OMP checkpoint/retirement/activation; the uncertain-successor cell retains its original launch-result loss, claimed-state restore and explicit unaccepted-state assertion. Ruling auto-approval originates from a real coordinator proposal. The authorized-writer cell uses a real Native OMP writer with independently observed consume-without-effect, claim-without-effect, exact append and helper resolution; unsupported-capability refusal still uses an ordinary terminal worker. All effects and private receipts remain in the disposable runtime, with existing cleanup unchanged.

Paired-migration qualification starts from genuine frozen C2 native stores. Mixed-version checks preserve ordinary launch history and require one additional ordinary effect while refusing managed pairing. A replaced legacy controller is continued only after both prior executors are proved replaced. Native refusals are observed on their actual receiving bridge or forwarded toast, not inferred from diagnostic wording. Source-loss cases preserve a real live worker, restore the exact captured source without replacing unrelated KV, and forbid new managed effects or migration controls for unreadable sources. Pending-effect cases compare the original persisted request bytes and grant before/after refusal; an already executed native effect is never replayed. Optional probe traces forward original callbacks unchanged and are not final-package capture evidence.

Ruling qualification uses the actual gate card, not an unsupported command gate attribute. Before the first owner input it observes current native idle evidence, consumed/compacted helper receipts and matching rendered authority. Empty-read evidence must be newer than native idle evidence; later metadata polls do not invalidate it. The fixed helper consumes receipts through its own interface; actual provider runs never receive fixture command files. Reply-receipt settlement stays inside the existing ACK deadline before the next input budget starts. Timers, authority fences and deadlines are unchanged; no captured approval is refreshed or replayed. Native Finish must prove exact stop and physical mailbox retirement before a local writer becomes eligible.

Isolated setup/lifecycle inputs permit at most one fresh native interaction after a positively correlated stale refusal proves that no effect started. This covers Pause/Resume, association opening, register/claim, catalog and Close opening. Separately approved assignment fixtures may enter the complete form once more only after the exact emitted control, captured revision/record and submitted request match the stale refusal, with unchanged work and no new dispatch effect. Private assignment tracing is enabled only for those instrumented scenarios; absent correlation evidence never permits another input, including in uninstrumented provider runs. Append-only ledgers retain both attempts. Original deadlines cover both attempts; silent loss, uncertain effects, a second refusal or changed source identity stop the step. No captured intent is refreshed or replayed.

Separately approved ordinary document fixtures permit one fresh complete owner attestation only after the exact native preparation request and consumed stale-refusal receipt are correlated, with unchanged ruling obligation, no write intent, unchanged durable bytes and unchanged participating buffer. Both attempts and hashes stay in a private ledger under the original deadline. Any started write, accepted preparation or settled obligation ends this input helper without another edit. Fault-injection, reissue and negative document scenarios retain single-shot inputs; this fixture permission does not change production retry or authority rules. Private tracing records preparation correlation fields, not document bodies.

Native prompt and picker helpers use the earlier of the enclosing operation deadline and any explicit input deadline. They recheck it immediately before confirmation/submission, and after native select-all before typing, so a prompt becoming visible in time cannot authorize input after the original deadline. Headless clock-boundary checks do not replace actual native qualification.

Uninstrumented native runs install the exact product packages through the normal installer; only the private driver stays linked. Source-copy and installed-file hash guards both remain mandatory. Retention qualification distinguishes positive exact worker stop and physical mailbox retirement from allocation-time work-record reclamation. Explicit session close must still remove every scoped record and physical mailbox identity while preserving ordinary unmanaged Exited history. Reloaded closing sessions retain their close fence without executable admission. Each soak window uses its own Config and controller; no foreign pane is mirrored.

Native retention sweeps decode actual span/text nodes and versioned dispatch, lease and execution payloads, including verified dispatch envelope bodies. A close is not fully observed until its native views have retired the closed scope. SPAWN refreshes live views after durable commits; ORCH acknowledges response-view consumption only after its matching `session_closed` alias is visible. SPAWN independently rechecks namespace, admission cursor, scope absence and outstanding bridge obligations before clearing the exact view. The close-after-reload case exercises this path; missing/corrupt sources, mismatched acknowledgements and other-scope challenges must retain the view.

Close preflight waits for local result consumption, not deletion of a peer receipt that authenticated Close itself acknowledges. It observes the current rendered source before the first input; stale input refusals are retained and never replayed. The focused native `orch:health/close_refusal` regression covers an earlier pre-effect reconciliation refusal, a newly approved Close, and refusal of that new Close: only the exact committed close ID may supersede the prior hold. Unresolved immutable controls remain live.

The optional `--retention-rehearsal` mode requires exactly `--scenarios lifecycle --runtime-cases lifecycle/retention/retention-native-rehearsal`. It runs 65 cycles and reports itself as non-qualifying, including on success; it cannot select or mix with the full soak. A separately authorized rehearsal runs only after shorter cells pass, under a 3,600-second outer supervisor cap, stopping on its first failure without automatic retry. Per-operation deadlines remain unchanged. Its cycle-timing ledger is diagnostic evidence, not a substitute for the mandatory 4,098-request/2,049-retired-owner/65-session soak. Rehearsal and full-soak authorizations are separate.

Product measurements and component measurements are separate. Product counters include actual native helper launches, loaded-codec hash input bytes, incoming SPAWN bridge events and successful native KV writes during the same report-to-ACK interval. Shell-tool/native-internal hashes are excluded. Sequential samples and polling overhead do not establish a latency improvement.

The runtime isolates configuration, daemon/control endpoints, HOME and XDG state, and reaps its owned processes. Actual screenshot pixels must be inspected separately from configured theme slots. Ordinary native Appearance preferences can override simulated system appearance.

The scratch directory uses a short `rn-` prefix because private Unix socket paths also contain the complete scenario name; use a short `TMPDIR` when selecting a custom scratch parent. The deterministic handover participant drains and resolves its retirement control, then stops invoking mailbox helpers while awaiting native stop. It must not reopen producer locks after declaring itself quiescent. This fixture behavior does not substitute for real-provider handover qualification.
