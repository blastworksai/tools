# Changelog

## 0.7.3

- Fix: a plan view's wait is held per requesting window (one window's revoke no longer cancels another's), and a wait that lapses leaves the view open and dormant until a window asks again, instead of closing it.
- Fix: a plan with several `active` entities (parallel builders) is no longer refused with "at most one active entity, named by current". Every active entity shows as active. `current` may be null or name one active or blocked entity; naming a pending, done or unknown entity, and every other shape rule (states, ids, duplicates, bounds, reasons), still refuses.

- Fix: turning **Sync Glitch Plan to Tern Board?** On no longer empties **Attach to**. Sessions on other hosts were dropped for sync as well as for the native board, so with every session remote the list vanished and the attach was cleared.
- Fix: sync is never silent. The pane names the board once it is synced (with an **Open board** control) or says what is missing: no session picked, the session closed, no plan view yet, no plan published, or a plan that could not be read. The board shown is tied to the session it was synced for: when another window moves the attachment, or the session closes, the old board name and **Open board** disappear. The window keeps its board memory, its "already synced" memory and the pane repaint in step on that one attachment: the old board disappears from an open pane at once, and returning to a session whose plan did not change brings its board and "synced" line back.
- Fix: attaching a session that has not published a plan yet, with sync On, no longer leaves a dead view. The plan view stays open and looks again every 5 seconds, so sync starts as soon as the plan is published. With sync Off the view still closes with its notice. A waiting view is saved, so after a plugin reload it resumes waiting instead of staying dead.
- Fix: board sync works when the session runs on another machine than the Tern window (multi-device). The plan view draws the plan it validated into one hidden, keyed node of its own pane, and the window reads that node through the pane surface, for a local and a remote session alike. Before, the host half wrote the plan, the attached target and the settings into its own machine's plugin store, and the window read its own, so a remote session never reached the board. The window now tells the view by event (not by plugin store) whether to keep waiting for a plan. A plan over the node cap (60000 bytes of JSON) is never sent cut: the pane says it is too large. When the window cannot read a remote session's plan it says: "Board sync for this session works only when the session runs on this window's machine." The old blanket "session on another host" blocker is gone.
- Fix: a successful sync can no longer leave the restored board invisible. The Settings pane is repainted whenever what it shows changes (mode, attachment, board name and link, status text), not only when the status text changes, so a pass that finishes with the same text as before still brings its board and **Open board** back.
- Fix: turning sync Off in another window now clears the board, **Open board** and the "synced" line here at the next tick, also while a pass is still running. Settings and mode changes are observed before any early return of the sync tick, and the "already synced" memory is reset with them.
- Fix: a waiting plan view that is restored after a restart is bound to the process it first saw (PID and birth time, reported by the helper), not to the PID alone. A PID reused by another session ends the wait with a notice instead of showing an unrelated plan or polling forever. The helper gains `discover --with-identity` and `--parent-birth`; its default answer is unchanged.
- Fix: the README no longer says "At most one is active"; it matches the several-active rule.
- Fix: with Glitch Off, when only sessions on other hosts are open, the list says that the board needs a session on this computer and how many were left out, instead of "No eligible session is open for this mode."
- Fix: a plan view that waits for a plan stops waiting when you move the attachment to another session, turn sync Off or close the attached session, and a view whose window stops asking for 15 seconds stops on its own, so no view polls forever.
- The Glitch Off control reads "Show the session's folder as a Tern Board?" instead of a bare "Board", so it is not mistaken for the Glitch sync setting.
- Turning sync on while a plan view is attached starts syncing on the next tick; the status is cleared whenever sync turns off or the attached session changes.
