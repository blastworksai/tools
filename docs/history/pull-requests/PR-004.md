## Description

v0.3.1: pairing and sessions that hold, upgrades that carry old ideas forward, and one shared ideas store.

- **A tab that lost its service says so.** When the service restarted on a new address, the old tab used to show nothing at all. It now shows a short panel telling the operator to reconnect from the terminal, with no link to the dead address and nothing editable behind it. A tab replaced by a newer one shows the same kind of panel with the steps hidden.
- **An agent that is still composing stays connected.** If the operator accepts a step by hand before the terminal's answer arrives, the late answer is refused for that request and the agent receives the next one, instead of being dropped.
- **Pairing codes wait for the operator.** The skill text issues a typed code only after the operator says ready, and the events loop restarts the moment a request is delivered.
- **Older ideas move forward on upgrade.** On the first open after an upgrade each idea is migrated one version at a time; the original bytes are kept in the idea's history, checked by hash on every load, and one plain line says what was updated. An idea that cannot be updated is held alone, named in its own sentence, and the rest of the store stays fully editable. Version 2 ideas become drafts to re-accept; capture and priorities keep their acceptance.
- **Runs on a shared home.** When the home folder is shared, the private runtime folder falls back to the OS runtime directory by itself; the privacy rule is unchanged.
- **One store for every seat.** A store whose root is a shared group folder is written for the group (files 0660, folders 2770, sealed assets 0440) and never for others.
- **Bringing ideas in and taking them out.** `import-idea` brings one idea in from another store, preview first, its history byte for byte and the source untouched. Its place in the new backlog is new, so the imported idea and any idea whose neighbours shift are marked to assess again ("Imported idea: check its assessment and position, then accept it again."), and Review never offers a planning prompt the backlog no longer supports. `remove-idea` is the one removal road, preview first, leaving a tombstone pinned in the index and sealed; an interrupted removal is finished on the next open, and a removed idea can be imported again (ordered by the backlog counter, never by clocks).
- **Follow-ups.** The Orca page record is pruned under a lock, the keep-alive log truncation is tested, and the private-words guard also reads tests and docs.
