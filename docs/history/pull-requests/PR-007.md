## Description

SKILLS-111..115: one-click link to the idea page from a Tern pane, through fixed ports and one standing tunnel.

## Why
Orca is retired and the cockpit is Tern on Windows attached to the VM. No VM pane can drive that browser (`tern browser open` answers `no_window`), but a printed link is clickable, and the VM's random `127.0.0.1` ports are unreachable from Windows.

## What changes
- **Fixed ports (SKILLS-111).** Optional `browser_port` / `prototype_port` (1024-65535, distinct). The service binds exactly that port; a taken port is `port_in_use` (or `prototype_port_in_use`), never a random fallback. Unset keeps today's behaviour byte for byte. SO_REUSEADDR on POSIX for TIME_WAIT restarts; SO_REUSEPORT never.
- **Link mode (SKILLS-112).** `browser-open --browser link` opens nothing and returns `browser.link` = origin + `#pair=<one-time code>`. `--browser` is optional on a seat with `browser_mode`. The pairing cookie gets `Max-Age=86400` so seats' cookies can't pile up past the bridge's 8 KB header line.
- **Skill and docs (SKILLS-113).** The agent shows the link at once on its own line and gets a fresh one with `--browser link --resume`.
- **Review rework.** A starting owner is never called `port_in_use` (decided at the readiness deadline); a service started on a random port before the config change is refused as `port_mismatch`.
- The estate kit (port registry, seat config writer, the Windows workstation tunnel wizard; SKILLS-114) lives outside this repo.
